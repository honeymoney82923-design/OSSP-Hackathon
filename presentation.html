01. Problem Statement & Motivation

The Memory Wall & Address Translation Bottleneck

Modern OS architectures use Virtual Memory for isolation and protection. However, every memory reference requires translation from Virtual Address to Physical Address.

The Challenge

  • Naive page table lookups double memory latency (1 access for Page Table + 1 for Data).
  • Multi-level page tables multiply latency by 3x to 5x.
  • Lack of intuitive visualization makes it hard to observe cache eviction & page fault penalties in real time.

Our Solution

  • Build a hardware-accurate simulator modeling TLB hit/miss and Page Fault behavior.
  • Provide real-time Effective Access Time (EAT) calculation.
  • Enable interactive parameter tuning (Page size, TLB size, LRU/FIFO).
02. System Architecture

Bit-Level Address Decomposition & Memory Layout

Given an N-bit Virtual Address with page size P = 2k bytes:

Virtual Address [16-bit] = [ VPN (Bits 15..k) | Offset (Bits k-1..0) ]
Physical Address = [ PFN (Frame #) | Offset (Bits k-1..0) ]

Translation Lookaside Buffer (TLB)

Fully associative on-chip hardware cache. Holds { Tag: VPN, Frame: PFN, Valid, LRU Age }. Provides sub-2ns lookup speed.

Page Table & Physical Memory

Page Table stores mapping of all process pages. Frames in RAM are allocated dynamically via Demand Paging on page faults.

03. Implementation & Algorithms

Translation Pipeline & Replacement Policies

The 4-Stage Translation Pipeline

1. Address Split: Compute VPN = VA >> k, Offset = VA & ((1 << k) - 1).

2. TLB Parallel Search: Check TLB entries. If Hit ➔ Form Physical Address in 2 ns.

3. Page Table Fallback: If Miss ➔ Lookup Page Table (100 ns). If Invalid ➔ Trigger Page Fault (8000 ns).

4. Cache Update: Insert into TLB via replacement policy.

Least Recently Used (LRU)

Tracks access timestamps. Evicts the entry whose last access was furthest in the past.

First-In, First-Out (FIFO)

Maintains allocation order. Evicts the oldest loaded entry regardless of access frequency.

04. Mathematical Verification

Effective Access Time (EAT) Analysis

We mathematically compute and validate the latency reduction achieved by the TLB:

EAT = H * (t_tlb + t_mem) + (1 - H) * (t_tlb + 2 * t_mem)

Where:
• H = TLB Hit Ratio
• t_tlb = TLB Access Time (typically 2 ns)
• t_mem = Main Memory Access Time (typically 100 ns)

Without TLB (Baseline)

Access Time = 2 * t_mem = 200 ns (100% overhead on every read/write).

With 90% TLB Hit Ratio

EAT = 0.90*(102ns) + 0.10*(202ns) = 91.8 + 20.2 = 112.0 ns (44% speedup!).

05. Testing, Benchmarking & Results

Experimental Workload Analysis

High Temporal Locality Benchmark

Repeated accesses to hot code loops (e.g. Pages 1 & 2). Result: TLB Hit Ratio > 87.5%, EAT drops to ~114 ns.

Sequential Scan Benchmark

Linear memory pass across adjacent memory addresses. Demonstrates spatial locality and periodic page crossings.

Loop Thrashing Benchmark

Accessing N+1 pages in a loop with an N-slot TLB. Demonstrates pathological FIFO/LRU eviction.
